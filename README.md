# 오늘 뭐먹지? 마이스누 학식 추천

서울대학교 학생을 위한 모바일 우선 학식 추천 MVP입니다. 식샤의 공개 식단을 날짜별로 불러오고, 직접 입력 또는 이미지 OCR로 빠진 식단을 등록합니다. 실제 먹은 메뉴의 칼로리 합계, 기기에 저장되는 관심 표시와 개인화 추천을 제공합니다.

## 실행

```powershell
npm.cmd install
npm.cmd run dev
```

브라우저에서 `http://localhost:3000`을 열어 확인합니다.

검증은 `npm test`, `npm run typecheck`, `npm run build`로 실행합니다.

## 기기 저장 방식

로그인과 서버 계정 저장은 사용하지 않습니다. 관심 표시, 날짜별 실제 섭취 기록, 하루 목표 칼로리, 선호 카테고리, 제외 재료, 직접 등록한 식단은 이 브라우저의 `localStorage`에 저장됩니다. 직접 수정한 칼로리도 날짜·메뉴별로 같은 기기에 저장됩니다. 다른 브라우저·기기로 동기화되지 않고, 브라우저 데이터를 지우면 사라집니다. 내 설정의 **내 데이터 모두 삭제**로 저장된 사용자 데이터를 지울 수 있습니다.

추천은 식샤 평점·인기, 이 기기의 관심 표시·섭취 이력·선호 카테고리, 직접 설정한 하루 목표 칼로리를 함께 반영합니다. 메뉴명에 드러난 제외 재료만 걸러낼 수 있으므로 알레르기 안전성은 식당에 직접 확인해야 합니다. 이미지 OCR은 Tesseract.js를 브라우저에서 실행합니다. 인식된 글자에서 가격·제목 등을 일부 제거한 뒤 반드시 사람이 확인하고 메뉴를 수정해야 합니다. 사진은 서버에 업로드하거나 저장하지 않지만, OCR 실행에 필요한 언어 파일은 인터넷에서 내려받습니다.

## 사용하는 방법

1. 홈에서 화살표 또는 날짜 입력으로 원하는 날짜를 선택합니다. 식샤에 해당 날짜 메뉴가 없으면 빈 상태로 표시됩니다. 연결이 실패한 **오늘**만 예시 식단을 명시적으로 보여줍니다.
2. 식당·끼니를 고르거나 메뉴명을 검색합니다. 실제 먹은 메뉴에만 **먹었어요**를 누르면 날짜별 기록과 칼로리 합계에 추가됩니다. 미래 날짜에는 기록할 수 없습니다. 이전 버전의 단순 체크 기록은 섭취 미확인으로 보존하되 합계에서 제외합니다.
3. 빠진 메뉴는 **식단 등록**에서 날짜·식당·끼니를 지정하고 한 줄에 하나씩 적습니다. 사진이 있다면 OCR로 글자를 읽어 입력란에 채운 후 잘못 인식된 내용을 고쳐 저장합니다.
4. **내 설정**에서 목표 유형이나 하루 목표 칼로리를 직접 바꿉니다. 숫자 입력 후 입력칸을 벗어나면 저장됩니다.
5. 메뉴 아래 **칼로리·분량 수정**에서 참고 1인분 대비 먹은 양을 고르거나, 실제 중량을 알 때 100g/100ml당 자료로 계산하거나, 영양표시의 kcal를 직접 입력합니다. **AI에게 묻기** 또는 하단 **AI 상담**에서는 메뉴와 추정 근거를 질문으로 복사한 뒤 ChatGPT를 새 탭에서 열어 대화할 수 있습니다. 질문은 자동으로 전송되지 않습니다.

기능 검토와 수정 내역, 남은 한계는 [개선점 목록](docs/IMPROVEMENTS.md)에 정리했습니다.

## 칼로리 정확도 개선 계획과 현재 구현

1. 완료: 식약처 [K-FIND 음식 DB](https://various.foodsafetykorea.go.kr/nutrient/general/down/list.do)의 2026-08-28 배포본에서 프랜차이즈 제공 수치를 제외하고 기준량과 음식 중량이 모두 있는 2,154개 자료를 추렸습니다. `lib/mfds-foods.ts`는 원본 엑셀 → `scripts/extract-mfds.ps1` → `scripts/build-mfds-reference.mjs` 순서로 만들었습니다. 각 결과에 원본 음식의 직접 링크와 에너지·기준량·참고 제공량을 표시합니다.
2. 완료: 100g/100ml당 열량을 참고 중량으로 환산합니다. 동일·유사 음식만 명시적으로 매칭하고 유사 음식일 때는 추가 재료가 반영되지 않았다고 표시합니다. 밥 포함 식단은 찌개와 쌀밥을 나눠 합산합니다. 알 수 없는 세트에 임의의 0.75인분 계수를 곱하던 계산은 없앴습니다. S/L/R 크기처럼 중량이 없는 메뉴, 뷔페, 구성품이 불명확한 음식에는 숫자를 만들지 않습니다. 이전 [외식 메뉴 참고값](https://www.foodsafetykorea.go.kr/portal/board/boardDetail.do?bbs_no=bbs039&menu_grp=MENU_NEW03&menu_no=4847&ntctxt_no=22484)은 새 DB에서 정확한 1인분 자료를 찾지 못한 일부 메뉴에만 낮은 신뢰도 대체값으로 사용합니다.
3. 완료: 메뉴마다 참고 제공량 대비 0.5/1/1.5/2인분으로 계산할 수 있습니다. 1인분 중량이 없는 음식도 공식 100g/100ml당 수치가 있으면 실제 먹은 중량을 입력해 계산할 수 있습니다. 영양표시의 kcal를 직접 입력할 수도 있습니다. 수정값은 이 브라우저에 날짜·메뉴별로 저장되며, 추정치로 되돌릴 수 있습니다. 기존 직접 등록 식단의 자동 추정은 새 규칙으로 갱신하되, 예전에 먹었다고 저장한 기록의 kcal는 과거 기록을 임의로 덮어쓰지 않습니다.
4. 남은 한계: 식샤 응답에 실제 제공 중량·조리법·영양표시가 없어 학식 실측치와의 오차율은 아직 검증하지 못했습니다. 표시 범위는 통계적으로 검증된 신뢰구간이 아닙니다. 식당별 실측 중량과 영양표시를 확보하고 사용자 수정값과 비교하여 오차를 측정하는 것이 다음 단계입니다. 현재 개인 수정값은 기기에만 저장되어 다른 사용자에게 전파되지 않습니다.

## AI 상담 탭에 대한 판단

정적 GitHub Pages 사이트는 OpenAI API 비밀키를 안전하게 보관할 서버가 없으므로 사이트 안에 가짜 대화창이나 브라우저 API 호출을 만들지 않았습니다. 대신 메뉴·현재 추정 근거·직접 확인한 분량을 질문으로 편집하고 복사해 [ChatGPT](https://chatgpt.com/)의 실제 대화 페이지를 새 탭으로 엽니다. 사용자가 붙여넣기 전에는 메뉴나 기록을 외부로 보내지 않습니다. AI의 답변 역시 검증된 칼로리 자료가 아니며, 필요한 경우 사용자가 답을 확인한 뒤 사이트의 칼로리 수정란에 반영합니다.

계산 규칙은 `lib/calories.ts`, 대표적인 오분류 회귀 검사는 `tests/calories.test.mjs`에 있습니다. 검사는 `node --test tests/calories.test.mjs`로 실행합니다. 범위는 측정된 오차율이 아닌 분량과 조리법이 달라질 수 있음을 보여주는 참고 범위입니다.
