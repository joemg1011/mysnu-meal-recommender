# 기능 검토 및 개선점

## 2026-11-24 계산 오류와 사용성 개선

- 국수·칼국수 변형이 ‘국’ 규칙에 먼저 걸려 면이 빠지던 계산 순서를 수정하고, 만둣국에는 만두와 국물을 함께 반영했습니다.
- 돈가스 등 이름이 있는 정식에 주요리·밥 200g·국 120g·반찬 60g을 가정합니다. 버거 세트는 감자튀김과 음료를 가정합니다. 분량과 구성은 근거에 표시하며 ‘밥 포함’ 중복 계산을 막았습니다.
- 연결 실패 때 예시 식단을 넣던 동작을 제거했습니다. 같은 날짜의 마지막 공개 식단을 최대 7건 캐시하고 저장 시각과 상태를 표시합니다. 12초 요청 제한, 날짜 변경 시 취소, 수동 재시도, 연결 복구 시 재요청을 추가했습니다.
- 이전 예시 식사 기록은 삭제하지 않고 합계에서 제외합니다. 손상된 저장값·불가능한 날짜를 검증하고, 내 기록에서도 미확인 칼로리 제외 개수를 표시합니다. 과거 실제 기록의 kcal는 보존합니다.
- 선택한 식당·검색어에 맞춰 추천하며 단독 밥·기본 반찬과 섭취 미확인 이력의 추천 가산을 제외합니다.
- 컴퓨터에서는 추천·섭취 합계와 식당 목록을 두 열로 배치하고 휴대폰에서는 한 열로 표시합니다. 메뉴별 긴 근거는 펼쳐보기로 정리하고, 탐색 아이콘·키보드 초점·버튼 상태를 개선했습니다. 외부 웹폰트 다운로드 의존성도 제거했습니다.
- OCR 작업 중 화면을 떠나면 작업자를 정리하고, 인식 도중 입력 변경으로 결과가 뒤섞이는 것을 막았습니다.
- 배포 시점의 날짜가 정적 HTML에 고정되지 않도록 브라우저에서 날짜를 초기화합니다.

계산·캐시·이전 기록·취소 요청을 포함한 21개 회귀 검사를 실행합니다. 열량은 실제 식당의 실측치가 아니며 낮은 신뢰도와 분량 가정 표시를 유지합니다.

## 2026-10-14 칼로리 정확도 개선

1. 기존 12개 메뉴 외에는 음식 종류별 고정 열량을 적용하고, 복수 주메뉴 세트에는 근거 없는 0.75인분 계수를 곱하던 문제를 수정했습니다. 식약처 음식 DB의 100g/100ml당 열량을 참고 제공량에 맞춰 계산하고 출처·가정·범위를 표시합니다.
2. 메뉴명만으로 분량·토핑을 알 수 없는 경우 정확해 보이는 숫자를 만들지 않습니다. 유사 메뉴의 자료를 적용한 경우에는 추가 재료 미반영·낮은 신뢰도를 명시합니다. S/L/R 크기, 복수 주메뉴 세트, 뷔페 등은 제공량 확인을 요청합니다.
3. ‘칼로리·분량 수정’에 인분 비율 계산을 추가하고, 영양표시가 있으면 직접 입력할 수 있도록 했습니다. 이전 직접 등록 식단도 새 추정 규칙으로 다시 표시하되 수동 수정값은 보존합니다.
4. ChatGPT 상담 탭을 추가했습니다. 서버와 비밀키가 없는 정적 사이트라 내장 대화 대신 질문 작성·복사와 실제 ChatGPT 대화 페이지로의 이동을 제공합니다. 자동 외부 전송은 없습니다.
5. 아직 실측 정확도는 검증하지 못했습니다. 식당의 실제 제공량·영양표시와 비교한 평균 절대 오차를 측정하고, 식당별 검증된 값을 우선 적용하는 후속 작업이 필요합니다.

## 이번 수정에서 해결

1. 날짜 화살표가 아무 동작도 하지 않음 → 전날·다음 날 식샤 API를 날짜별로 조회하고, 직접 날짜 선택·오늘 복귀를 추가.
2. 오늘 이외 메뉴를 볼 수 없음 → 과거·미래 식단 조회, 날짜별 등록 식단 복원, 끼니·식당 필터 유지. 날짜가 바뀌면 식당 필터 초기화.
3. 체크의 목적이 불명확함 → `먹었어요`/`먹은 기록 취소`로 명시하고 실제 섭취 기록·칼로리 합계에 연결. 미래 메뉴는 섭취 기록 불가. 이전 버전의 모호한 체크는 섭취 미확인으로 보존하되 합계에서 제외.
4. 식단 등록의 위치와 방법이 불분명함 → 홈의 `빠진 식단 직접 등록`과 하단 `식단 등록` 동선을 유지하고 입력 순서·날짜·식당·끼니·메뉴 예시를 제공.
5. 예시 메뉴가 입력돼 있어 실제 식단으로 잘못 저장될 수 있음 → 빈 입력란과 유효성 검사로 변경.
6. 이미지 업로드가 실제 글자를 읽지 않는 데모였음 → 기기에서 실행되는 한글·영어 OCR로 교체. 가격·제목 등 잡음을 일부 제거하고 편집 가능한 결과를 제공.
7. 목표 칼로리가 세 개 고정값뿐임 → 하루 목표를 숫자로 직접 설정·저장하고 합계·추천에 반영.
8. 알림, 식당 더보기, 상세 보기, 관리자 검수 버튼이 실제 동작하지 않거나 가짜 데이터였음 → 해당 허위 UI 제거. 메뉴 상세 정보와 메뉴별 식샤 평점은 실제 메뉴 행에 표시.
9. 식당·메뉴가 많아 찾기 어려움 → 식당·메뉴 검색 추가.
10. 식샤 연결 전 예시 식단이 실제 메뉴처럼 표시됨 → 로딩 상태에는 빈 화면을 표시하고, 실패한 오늘에만 예시 식단임을 밝힘. 다른 날짜 연결 실패는 오류 상태로 표시.
11. 관심 표시가 같은 이름의 다른 날짜 메뉴로 이어지지 않음 → 메뉴 이름을 기준으로 기기 내 선호를 누적. 이전 저장 방식도 읽도록 유지.
12. 직접 등록한 식단을 지울 수 없음 → 해당 식단과 연결된 섭취 기록·칼로리 수정값을 함께 삭제하는 버튼 추가.

## 여전히 제한되는 부분

- 식샤의 공개 API에 메뉴가 없거나 서비스가 중단되면 실제 식단을 표시할 수 없습니다. 날짜별 결과를 보장하지 않습니다.
- OCR은 글자 인식이며 식당명·날짜·끼니를 확정하지 않습니다. 사용자가 확인·수정해야 합니다. 모바일 기기에서는 첫 언어 파일 다운로드와 분석에 시간이 걸릴 수 있습니다.
- 칼로리는 해당 식당의 실측치가 아닌 식품 참고값·분량 가정입니다. 식사 기록은 사용자가 누른 메뉴만 포함합니다.
- 메뉴명만으로 알레르기 재료를 완전히 알 수 없습니다. 식당에 직접 확인해야 합니다.
- 기기 저장 방식을 유지하는 동안 여러 사용자의 투표 집계, 계정 간 동기화, 운영자 공동 검수, 공유 후기는 제공할 수 없습니다. 식샤에서 받은 평점·인기도와 이 기기의 관심·섭취 기록은 구분해 표시합니다.
