# 기능 검토 및 개선점

## 이번 수정에서 해결

1. 날짜 화살표가 아무 동작도 하지 않음 → 전날·다음 날 식샤 API를 날짜별로 조회하고, 직접 날짜 선택·오늘 복귀를 추가.
2. 오늘 이외 메뉴를 볼 수 없음 → 과거·미래 식단 조회, 날짜별 등록 식단 복원, 끼니·식당 필터 유지. 날짜가 바뀌면 식당 필터 초기화.
3. 체크의 목적이 불명확함 → `먹었어요`/`먹은 기록 취소`로 명시하고 실제 섭취 기록·칼로리 합계에 연결. 미래 메뉴는 섭취 기록 불가. 이전 버전의 모호한 체크는 섭취 미확인으로 보존하되 합계에서 제외.
4. 식단 등록의 위치와 방법이 불분명함 → 홈의 `빠진 식단 직접 등록`과 하단 `식단 등록` 동선을 유지하고 입력 순서·날짜·식당·끼니·메뉴 예시를 제공.
5. 예시 메뉴가 입력돼 있어 실제 식단으로 잘못 저장될 수 있음 → 빈 입력란과 유효성 검사로 변경.
6. 이미지 업로드가 실제 글자를 읽지 않는 데모였음 → 기기에서 실행되는 한글·영어 OCR로 교체. 가격·제목 등 잡음을 일부 제거하고 편집 가능한 결과를 제공.
7. 목표 칼로리가 세 개 고정값뿐임 → 하루 목표를 숫자로 직접 설정·저장하고 합계·추천에 반영.
8. 알림, 식당 더보기, 상세 보기, 관리자 검수 버튼이 실제 동작하지 않거나 가짜 데이터였음 → 해당 허위 UI 제거. 메뉴 상세 정보와 메뉴별 식샤 평점은 실제 메뉴 행에 표시.
9. 식당·메뉴가 많아 찾기 어려움 → 식당·메뉴 검색 추가.
10. 식샤 연결 전 예시 식단이 실제 메뉴처럼 표시됨 → 로딩 상태에는 빈 화면을 표시하고, 실패한 오늘에만 예시 식단임을 밝힘. 다른 날짜 연결 실패는 오류 상태로 표시.
11. 관심 표시가 같은 이름의 다른 날짜 메뉴로 이어지지 않음 → 메뉴 이름을 기준으로 기기 내 선호를 누적. 이전 저장 방식도 읽도록 유지.
12. 직접 등록한 식단을 지울 수 없음 → 해당 식단과 연결된 섭취 기록·칼로리 수정값을 함께 삭제하는 버튼 추가.

## 여전히 제한되는 부분

- 식샤의 공개 API에 메뉴가 없거나 서비스가 중단되면 실제 식단을 표시할 수 없습니다. 날짜별 결과를 보장하지 않습니다.
- OCR은 글자 인식이며 식당명·날짜·끼니를 확정하지 않습니다. 사용자가 확인·수정해야 합니다. 모바일 기기에서는 첫 언어 파일 다운로드와 분석에 시간이 걸릴 수 있습니다.
- 칼로리는 해당 식당의 실측치가 아닌 식품 참고값·분량 가정입니다. 식사 기록은 사용자가 누른 메뉴만 포함합니다.
- 메뉴명만으로 알레르기 재료를 완전히 알 수 없습니다. 식당에 직접 확인해야 합니다.
- 기기 저장 방식을 유지하는 동안 여러 사용자의 투표 집계, 계정 간 동기화, 운영자 공동 검수, 공유 후기는 제공할 수 없습니다. 식샤에서 받은 평점·인기도와 이 기기의 관심·섭취 기록은 구분해 표시합니다.
